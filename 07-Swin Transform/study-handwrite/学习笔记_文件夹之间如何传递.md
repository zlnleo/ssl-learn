# 学习笔记：不同文件夹之间的内容怎么"传递"（study-handwrite 为例）

> 配合《修改记录.md》一起看。本文回答两个问题：
> 1. **import 层面**：`model/`、`utils/`、`train.py` 这几个文件夹/文件之间，代码是怎么互相引用的？
> 2. **运行时数据层面**：训练时数据（图像→token→窗口→…→loss）和尺寸信息是怎么在模块之间一层层传下去的？

---

## 0. 先看清目录结构

```
study-handwrite/                ← 顶层 = "项目根"，train.py 的 sys.path 锚点
├── train.py                    ← 顶层脚本：数据 + 训练循环 + 调模型
├── model/                      ← "模型包"：Swin 是怎么搭起来的
│   ├── __init__.py             ← 有这个文件，model/ 才是"包"（不是普通文件夹）
│   ├── patch.py                ← PatchMerging（6 模块）
│   ├── window.py               ← 窗口切分/还原、注意力掩码（2/5 模块）
│   ├── attention.py            ← WindowAttention（1/3 模块）
│   ├── block.py                ← SwinBlock（7 模块）
│   ├── layer.py                ← BasicLayer（8 模块）
│   └── model.py                ← SwinTransformer 总装（9 模块）
└── utils/                      ← "工具包"：与具体网络结构无关的杂项
    ├── __init__.py
    ├── position.py             ← 相对位置索引表
    ├── utils.py                ← DropPath
    └── save.py                 ← checkpoint 存取
```

类比：`model/` 是"整车厂"（每个零件一个文件，互相装），`utils/` 是"标准件仓库"（谁都能来拿），`train.py` 是"试车员"（只管把车开起来，不关心零件怎么造）。

---

## 1. 两个"传递"要分开理解

| 层面 | 传递的内容 | 发生的时机 | 机制 |
|---|---|---|---|
| **import（引用）** | 类、函数、模块 | 程序启动时（import 时执行一次） | `from xxx import yyy` + `sys.path` 搜索 |
| **运行时数据（传参）** | 张量、尺寸 H/W、mask、args | 训练循环里每一刻 | 函数调用参数 + 返回值 |

一个常见误区：以为 import 了就能"自动共享变量"。不是的——**import 只共享"定义"，不共享"运行时的值"**。比如 `train.py` 里建的 `model` 和 `save.py` 里的函数是两个东西，靠的是"把 model 当参数传进去"。

## 2. import 层面：代码怎么引用别的文件夹

### 2.1 三个前提条件（缺一不可）

```python
# 1) 被引用的文件夹必须是"包"：里面有 __init__.py（哪怕是空的）
#    → 所以本次给 model/、utils/ 各加了一个 __init__.py

# 2) 目标文件夹必须能在 sys.path 里被找到
#    → train.py 顶部这两行，把 study-handwrite 自己放进搜索路径：
import os, sys
_ROOT = os.path.dirname(os.path.abspath(__file__))   # = .../study-handwrite
if _ROOT not in sys.path:
    sys.path.insert(0, _ROOT)

# 3) 导入语句要"从包的根开始写全"，也就是绝对导入
from model.model import SwinTransformer      # 从 study-handwrite 开始：model/model.py
from utils.save import save_checkpoint       # 从 study-handwrite 开始：utils/save.py
```

> `sys.path` 就是"Python 去哪里找 import"的名单，`import` 会按名单顺序逐个目录找 `名字/__init__.py` 或 `名字.py`。
> 只要你在 `study-handwrite` 目录下运行 `python train.py`，脚本所在目录会自动成为 `sys.path[0]`，
> 所以 import 一定找得到；`_ROOT` 那两行是"保险"，让你在别的目录运行时也能 `python study-handwrite/train.py`。

### 2.2 包内部怎么互相引用（重点）

同一个包内部、跨文件引用，**也要写包前缀**，不能只写文件名：

```python
# model/block.py 想用 model/attention.py 里的 WindowAttention：
from model.attention import WindowAttention   # ✔ 正确（现在）
from attention import WindowAttention         # ✘ 原写法（裸导入，只在 model/ 本身也在 sys.path 时碰巧能过）
from .attention import WindowAttention        # ？相对导入，见下方说明
```

### 2.3 为什么这里不用相对导入 `from .attention import`？

相对导入以"当前模块的包层级"为锚：`model/block.py` 里 `.` = `model` 包本身，没问题；
但 `model/attention.py` 想用 `utils/position.py`，就得写 `from ..utils.position import ...`
（`..` = `model` 的父包 = study-handwrite），而 study-handwrite 只有在**被当成一个包 import** 时才有"父包"概念。

本项目是 `python train.py` 直接跑脚本：此时 study-handwrite 只是 sys.path 上的一个普通目录，
`model` 和 `utils` 是两个**并列的顶层包**，不存在"父包"，于是抛：

```
ImportError: attempted relative import beyond top-level package
```

所以结论：**多个并列子包 + 脚本直跑的场景，用"以项目根为锚的绝对导入"最稳**（本次就这么改的）。
相对导入适合"单一包 + `python -m 包.模块` 方式运行"（工程包 `swin/` 就是这种，见 2.5）。

### 2.4 完整 import 关系图（谁 import 谁）

```
                         ┌──────────────────────────────┐
                         │         train.py             │
                         └──────────────────────────────┘
        │ from model.model import SwinTransformer  │ from utils.save import save/load_checkpoint
        ▼                                          ▼
┌─────────────────┐  from model.patch ──► ┌──────────────────┐
│   model/model.py│  from model.layer ──► │  model/layer.py  │
└─────────────────┘                       └──────────────────┘
                                                 │ from model.block
                                                 ▼
                                    ┌──────────────────────┐
                                    │     model/block.py   │
                                    └──────────────────────┘
                       from model.attention  │    │  from model.window
                                            ▼    ▼
                            ┌──────────────────────┐   ┌────────────────────┐
                            │  model/attention.py  │   │  model/window.py   │
                            └──────────────────────┘   └────────────────────┘
                                          │ from utils.position
                                          ▼
                                   ┌──────────────┐
                                   │utils/position│    utils/utils.py (DropPath) ← block 也用它
                                   └──────────────┘    utils/save.py    ← 只被 train.py 用
```

画成"包"的视角更简单：

```
study-handwrite（sys.path 锚点）
├── model:   model → layer → block → attention / window / patch      （一层依赖一层）
└── utils:   position / utils / save   ← model 里 attention/block 引用 position、utils；
                                          train.py 引用 save
```

### 2.5 对照：工程包 swin/ 为什么用相对导入

同级目录 `07-Swin Transform/swin/` 是**单包结构**（所有模块塞进一个 `swin/` 包），
包内模块互相引用写 `from .attention import ...`（`.` 都是指 `swin` 这个包，永远有效），
对外只暴露 `swin/__init__.py` 里的名字（如 `from swin import build_swin`）。
因为只有一层包、没有"并列子包"问题，所以相对导入既安全又不怕改名冲突。

> 一句话记忆：**单包 → 相对导入（`.`）；多并列子包 + 脚本直跑 → 从项目根写全的绝对导入。**

## 3. 运行时数据层面：张量怎么一层层传

模型内部几乎每个 forward 都接收 `(x, H, W)`，`H/W` 是"几何状态"（token 网格多大），
随 PatchMerging 一起减半；这是 Swin 跟 ViT 很不一样的地方。

### 3.1 train.py → 模型（入口）

```python
# train_one_epoch 里：
images, labels = batch              # images: (B,3,H,W)
scores = model(images)              # logits: (B, num_classes)
loss = criterion(scores, labels)    # 标量 → backward
```

### 3.2 模型内部数据流（shape 跟踪，迷你配置 embed=128）

迷你配置：`patch=4, window=4, depths=(2,2,2), heads=(4,8,16)`，输入 32×32：

```
SwinTransformer.forward_features(x)            x: (B,3,32,32)
│  H, W = 32//4, 32//4 = 8, 8                  ← patch 后的网格尺寸
├─ patch_embed: Conv2d stride=4                → (B,128,8,8)
├─ flatten(2).transpose(1,2)                   → (B, 64, 128)    token 序列
│
├─ Stage0 BasicLayer(x, H=8, W=8)   dim=128, heads=4, depth=2
│    ├─ block0 (W-MSA,   shift=0):  输出 (B,64,128)
│    ├─ block1 (SW-MSA,  shift=2):  输出 (B,64,128)     ← 关键：H,W 不变，只有 merging 才减半
│    └─ PatchMerging                输出 (B,16,256)；H,W ← (8+1)//2=4
│
├─ Stage1 BasicLayer(x, H=4, W=4)   dim=256, heads=8
│    └─ ... PatchMerging            输出 (B,4,512)； H,W ← 2
│
├─ Stage2 BasicLayer(x, H=2, W=2)   dim=512, heads=16（无 merging）
│    └─ 输出 (B,4,512)
│
├─ self.norm                        → (B,4,512)   ← 所有 stage 结束才 norm 一次
└─ x.mean(dim=1)                    → (B,512)     全局平均池化
head(x)                             → (B,100)
```

### 3.3 块内怎么"切窗—注意力—还原"（SwinBlock 内部传递）

以 8×8 网格、window=4 为例，一个 SW-MSA block 内部：

```
输入 x: (B, 64, C)
  norm1 → view(B, H, W, C) = (B,8,8,C)
  pad 到 window 整数倍          → (B,8,8,C)（本来就整除，不 pad）
  torch.roll(-shift)            → 循环移位
  window_partition              → (B*nW, 4,4,C)，nW=(8/4)²=4
  view(-1, 16, C) = (B_,N,C)    ← B_=B*nW, N=M²=16
  WindowAttention(x, mask)      ← mask: (nW,16,16)，由 _get_mask 惰性构造
  view 回窗口 → window_reverse → (B,8,8,C)
  roll(+shift) → crop 回 (B,8,8,C) → view(B,64,C)
  残差 shortcut + DropPath(attn 输出)
  残差 + DropPath(MLP(norm2(x)))
输出 (B,64,C)
```

**注意**：`WindowAttention` 一次处理"所有 batch × 所有窗口"，所以它收到的 `B_` 是
`B*nW`；而 `mask` 只跟窗口几何有关、和 batch 无关，所以形状是 `(nW,M²,M²)`，
在注意力内部靠 `view(B_//nW, nW, ...) + mask.unsqueeze` 广播回每个样本。这是 Swin 实现里最容易晕的一步。

### 3.4 "只传定义 vs 传值"最容易踩的坑

| 场景 | 正确姿势 |
|---|---|
| train.py 想用 model 的权重 | 不是 import 就共享：把 `model` 当参数传给 `train_one_epoch(model, ...)` / `save_checkpoint(path, model, ...)` |
| 想让相对位置索引表跟着模型走 | 在 `WindowAttention.__init__` 里 `register_buffer(...)`，`.to(device)` 时自动带走，**不要**在 utils 里建全局变量 |
| mask 每次前向都要重新算吗 | 不需要：只依赖 `(H,W,shift,window)` → block 里缓存 `_mask_cache`，key 变了才重建 |
| H/W 信息 | 不放在张量里，作为函数参数 `layer(x, H, W)` 一路显式传递并随 merging 更新 |

## 4. 给初学者的三条"检查清单"

1. **import 报 ModuleNotFoundError / No module named 'model'**
   → 检查是不是没在 `study-handwrite` 目录下运行，或少了 `sys.path` 注入（train.py 顶部已处理）。
2. **import 报 attempted relative import beyond top-level**
   → 你把 `from .xxx` / `from ..xxx` 用在了"并列子包 + 脚本直跑"的结构里，改成从根写全的绝对导入（第 2.3 节）。
3. **张量 shape 对不上**
   → 在 `SwinBlock.forward` 里打印 `x.shape` 与 `H,W`，对照 3.2 的表；窗口注意力前后 `B_` 与 `B` 会差 `nW` 倍，属于正常现象。
