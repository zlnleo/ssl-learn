# 07 · 训练骨架速查：optimizer / scheduler / scaler 的标准姿势

> 回答"这个流程必须长那样吗"+"以后写训练代码照着抄"两个问题。
> 本文件是纯模板速查，原理详见 `06_scaler与scheduler完全讲解.md`。

---

## 一、先回答：必须长那样吗？

**分两层看：**

1. **batch 内的五步顺序是固定的**（因果链，不能乱）：

```python
optimizer.zero_grad()      # ① 清梯度（不清会累加上一批的）
logits = model(x)          # ② 前向
loss = criterion(...)      #
loss.backward()            # ③ 反向（算出梯度）
clip_grad_norm_(...)       # ④ 裁剪（可选但推荐）
optimizer.step()           # ⑤ 更新参数
```

2. **但"用哪些组件"是可选的**——scaler、scheduler、裁剪都不是必需品：

| 组件 | 职责 | 必须有吗 |
|---|---|---|
| optimizer | 更新参数 | ✅ 必须有 |
| scheduler | 控制学习率曲线 | 可选（但强烈建议） |
| scaler (AMP) | 保护 fp16 梯度 | 只有 fp16 混合精度才需要 |
| clip_grad_norm | 防梯度爆炸 | 可选（Transformer 系建议加） |
| EMA | 参数滑动平均 | 自监督（BYOL/DINO）标配 |

**所以答案是**：train.py 现在的样子是"标准 AMP 组合"；换场景就换组合，下面四种模板照着抄。

## 二、四种标准模板（复制即用）

### 模板 1：最简 fp32（CPU / 教学 / 快速实验）

```python
criterion = nn.CrossEntropyLoss()
optimizer = torch.optim.AdamW(model.parameters(), lr=1e-3, weight_decay=0.05)

for epoch in range(epochs):
    model.train()
    for x, y in train_loader:
        x, y = x.to(device), y.to(device)
        optimizer.zero_grad(set_to_none=True)   # ①
        logits = model(x)                        # ②
        loss = criterion(logits, y)
        loss.backward()                          # ③
        torch.nn.utils.clip_grad_norm_(model.parameters(), 1.0)  # ④ 可选
        optimizer.step()                         # ⑤
```

### 模板 2：标准 AMP fp16（GPU 通用 = train.py 现状）

```python
scaler = torch.amp.GradScaler("cuda", enabled=True)

for x, y in train_loader:
    x, y = x.to(device), y.to(device)
    optimizer.zero_grad(set_to_none=True)
    with torch.autocast(device_type="cuda", dtype=torch.float16, enabled=True):
        logits = model(x)
        loss = criterion(logits, y)
    scaler.scale(loss).backward()          # 放大再反向
    scaler.unscale_(optimizer)             # 还原（必须先于裁剪！）
    torch.nn.utils.clip_grad_norm_(model.parameters(), 1.0)
    scaler.step(optimizer)                 # 带 inf/nan 检查的更新
    scaler.update()                        # 调整放大系数
```

### 模板 3：bf16（Ampere 架构以上 GPU，无需 scaler）

```python
for x, y in train_loader:
    x, y = x.to(device), y.to(device)
    optimizer.zero_grad(set_to_none=True)
    with torch.autocast(device_type="cuda", dtype=torch.bfloat16, enabled=True):
        logits = model(x)
        loss = criterion(logits, y)
    loss.backward()                        # 注意：没有 scaler 包装
    torch.nn.utils.clip_grad_norm_(model.parameters(), 1.0)
    optimizer.step()
```

### 模板 4：加 EMA（BYOL / DINO 自监督训练的标配——你 SSL 主线会用到）

```python
ema = ModelEmaV2(model, decay=0.999)  # timm 提供；原理：参数朝滑动平均缓慢靠拢
for x, y in train_loader:
    ... 正常的 模板1/2 训练步骤 ...
    ema.update(model)                  # 每个 batch 后更新平均影子
# 验证/保存时用 ema.module（更稳的参数），不是 model
```

## 三、scheduler 一行配置速查

```python
# 每 N 个 epoch 衰减一次
scheduler = torch.optim.lr_scheduler.StepLR(optimizer, step_size=30, gamma=0.1)

# 指定 epoch 处衰减（ResNet 经典：30/60/90 各除 10）
scheduler = torch.optim.lr_scheduler.MultiStepLR(optimizer, milestones=[30, 60, 90], gamma=0.1)

# 余弦衰减（ViT/Transformer 标配，train.py 用它）
scheduler = torch.optim.lr_scheduler.CosineAnnealingLR(optimizer, T_max=epochs)

# 单周期先升后降（大 batch 训练常用；注意它是【按 batch】调度的！）
scheduler = torch.optim.lr_scheduler.OneCycleLR(optimizer, max_lr=1e-3,
                                                total_steps=len(train_loader) * epochs)

# 验证指标不涨才衰减（注意 step 要传验证 loss！）
scheduler = torch.optim.lr_scheduler.ReduceLROnPlateau(optimizer, mode="min", patience=3)
# 用法：scheduler.step(val_loss)   ← 和上面几种不一样，要传参数

# warmup + cosine（研究训练标配：先线性爬升 W 个 epoch 再余弦衰减）
def lr_lambda(epoch):
    if epoch < W:
        return epoch / W            # warmup：线性升到峰值
    return 0.5 * (1 + math.cos(math.pi * (epoch - W) / (epochs - W)))
scheduler = torch.optim.lr_scheduler.LambdaLR(optimizer, lr_lambda)
```

**调用位置口诀**：`StepLR/MultiStepLR/CosineAnnealingLR/LambdaLR/ReduceLROnPlateau` 在 **epoch 循环**里调 `scheduler.step()`；`OneCycleLR` 在 **batch 循环**里调。

## 四、断点续跑模板（train.py 已内置，这是原理版）

**保存（每个 epoch）**——四件套缺一不可：

```python
torch.save({
    "model_state": model.state_dict(),          # 权重
    "optimizer_state": optimizer.state_dict(),  # Adam 的动量/二阶矩
    "scheduler_state": scheduler.state_dict(),  # lr 走到了哪个位置
    "scaler_state": scaler.state_dict(),        # AMP 放大系数
    "epoch": epoch, "best_acc": best_acc,
    "config": config,
}, "checkpoint/last.pt")
```

**恢复**：

```python
ckpt = torch.load("checkpoint/last.pt", map_location=device, weights_only=False)
model.load_state_dict(ckpt["model_state"])
optimizer.load_state_dict(ckpt["optimizer_state"])
scheduler.load_state_dict(ckpt["scheduler_state"])
scaler.load_state_dict(ckpt["scaler_state"])
start_epoch = ckpt["epoch"] + 1
best_acc = ckpt["best_acc"]
```

**四个注意点**：
1. `weights_only=False`：checkpoint 里有 dict/字符串，纯张量模式会拒载；
2. `map_location=device`：存档在 GPU 上存的、恢复到 CPU 也能读；
3. **少存一个状态 = 假续跑**：只存模型权重，恢复后优化器动量清零、lr 曲线重走——训练会"接不上"；
4. resume 时 `--epochs` 表示"总共训练轮数"，要 ≥ 上次已跑的 epoch 数。

## 五、常见坑 TOP 5

| 坑 | 症状 | 解法 |
|---|---|---|
| scheduler.step() 放错层 | OneCycleLR 曲线全乱 | 查文档确认 epoch 级还是 batch 级 |
| unscale 前就裁剪 | 阈值失真 | 顺序：scale → backward → **unscale** → clip → step |
| resume 只存了模型 | 恢复后 loss 突跳 | 四件套一起存 |
| store_true 参数传了值 | `unrecognized arguments: True` | 开关参数不带值 |
| 日志只 print 不落盘 | 崩了一次什么都没留下 | 写文件 + flush（train.py 已做） |

## 六、一句话总结

> **optimizer 管"怎么更新参数"，scheduler 管"学习率怎么变"，scaler 管"fp16 数值别崩"，EMA 管"参数更稳的副本"，断点续跑管"状态不丢"。**
