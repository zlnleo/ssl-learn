## 一、eval.py：加载 checkpoint 复现 best_acc（必会）

训练和推理要**分开**：train.py 管训练，eval.py 管"拿最优模型测一把"。

```python
# eval.py（最小可用版）
import argparse
import torch

from vit import ViT                      # 或 vit_solution

parser = argparse.ArgumentParser()
parser.add_argument("--ckpt", type=str, default="checkpoint/best.pt")
parser.add_argument("--batch-size", type=int, default=128)
args = parser.parse_args()

ckpt = torch.load(args.ckpt, map_location="cpu", weights_only=False)

# 关键：必须用保存时的 config 重建模型，再灌权重——结构对不上会报 shape 错
model = ViT(**ckpt["config"]).eval()
model.load_state_dict(ckpt["model_state"])
print(f"checkpoint 记录的 best_acc: {ckpt['best_acc']:.4f} @ epoch {ckpt['epoch']}")

# 接数据集（复用 train.py 的 build_cifar100_loaders）测一遍，数字应该能对上
```

**单张图推理示例**（部署的雏形）：

```python
from torchvision import transforms
from PIL import Image

img = Image.open("cat.jpg").convert("RGB")
t = transforms.Compose([transforms.Resize(32), transforms.ToTensor(),
                        transforms.Normalize((0.5071, 0.4865, 0.4409),
                                             (0.2673, 0.2564, 0.2762))])
x = t(img).unsqueeze(0)                 # (1, 3, 32, 32)
with torch.no_grad():
    logits = model(x)                   # 推理三件套：no_grad + eval + 不建梯度
pred = logits.argmax(-1).item()
print("predicted class:", pred)
```

## 二、ONNX 导出：跨框架交换格式（会用）

ONNX 是"模型的中立格式"：PyTorch 训练 → 导出 ONNX → 各种部署框架（onnxruntime/TensorRT）加载加速。

```python
# export_onnx.py
import torch

ckpt = torch.load("checkpoint/best.pt", map_location="cpu", weights_only=False)
model = ViT(**ckpt["config"]).eval()
model.load_state_dict(ckpt["model_state"])

dummy = torch.randn(1, 3, 32, 32)                       # 一份样例输入定形状
torch.onnx.export(
    model, dummy, "vit_cifar100.onnx",
    input_names=["image"], output_names=["logits"],
    dynamic_axes={"image": {0: "batch"}},               # batch 维动态，任意 batch 可推理
)
```

**验证导出的模型**（onnxruntime 推理，速度通常快于原生 PyTorch）：

```python
pip install onnx onnxruntime
# 然后：
import onnxruntime as ort
sess = ort.InferenceSession("vit_cifar100.onnx")
outs = sess.run(None, {"image": x.numpy()})             # 输出和 PyTorch 版应一致
```

**为什么工业界爱用 ONNX**：跨框架（TF/PyTorch 通用）、跨硬件、方便做后续优化。面试常问"训练模型怎么部署"——答案链条就是：**训练(py) → export(onnx) → 推理引擎(onnxruntime/TensorRT)**。

## 三、TensorRT 与量化（了解，面试前深入）

- **TensorRT**：NVIDIA 的推理加速引擎，把 ONNX 转成高度优化的引擎，fp16/int8 下能快 2-10 倍；
- **量化（int8）**：把权重和计算从 fp32 压到 int8，速度↑、显存↓、精度略降（要校准）；
- **TorchScript**：PyTorch 自己的序列化方案（`torch.jit.trace`），无第三方依赖，内部部署常用。

先记住名词和位置即可，具体 API 等实际部署需求出现再学，一次用一次记。
