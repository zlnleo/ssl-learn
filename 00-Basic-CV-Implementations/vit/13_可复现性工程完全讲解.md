## 一、可复现性的四层（缺一层都不算完整）

```
① 代码层：固定种子 + 关闭非确定性算子
② 数据层：数据版本固定 + 划分固定
③ 环境层：torch/cuda 版本冻结（requirements.txt）
④ 记录层：超参/config/结论留档（runs/ + wandb，你已有）
```

---

## 二、① 代码层：种子与确定性

```python
import torch
import random
import numpy as np

def set_seed(seed: int):
    random.seed(seed)                          # Python 自带随机
    np.random.seed(seed)                       # numpy
    torch.manual_seed(seed)                    # CPU
    torch.cuda.manual_seed_all(seed)           # 所有 GPU

    # 牺牲一点速度换确定性：cudnn 的一些卷积算法是非确定的
    torch.backends.cudnn.deterministic = True
    torch.backends.cudnn.benchmark = False     # benchmark 会挑最快但不确定的算法
```

train.py 已做了前四行，补上最后两行就是完整版（注意注释：确定性开关会让训练略慢，但复现优先）。

**还有一个隐藏坑：DataLoader 的随机性**。开了 num_workers 后，每个子进程有自己的随机状态，数据增强的随机数不受主进程种子控制：

```python
def worker_init_fn(worker_id):
    worker_seed = torch.initial_seed() % 2**32  # 主进程种子派生
    np.random.seed(worker_seed)
    random.seed(worker_seed)

DataLoader(..., num_workers=2, worker_init_fn=worker_init_fn)
```

**"复现不了"的高频原因排行榜**：忘记种子 → 数据划分随机 → num_workers 随机性 → cudnn 非确定 → 环境版本不一致。

## 三、③ 环境层：把环境"冻"起来

```bash
pip freeze > requirements.txt          # 当前环境所有包和版本
conda env export > environment.yml     # conda 环境完整导出
```

```bash
pip install -r requirements.txt        # 别人（或三个月后的你）原样恢复
conda env create -f environment.yml
```

**记录三件套**（写进 README 或实验笔记）：

```
torch 2.5.1, cuda 12.4, python 3.11
requirements.txt 见仓库
```

面试金句："我的实验记录里包含完整的环境版本和依赖清单，任何实验都能在另一台机器重建环境重跑。"

## 四、② 数据层：划分固定

- 随机划分数据集时把 seed 写进代码/配置，划分结果存成文件（train.txt/val.txt），下次直接读文件而不是重新随机；
- 数据增强的强度写进 config（augmentation 是超参数的一部分，换增强 = 换实验）。
